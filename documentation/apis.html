OFFICER /api/officer/* Officer / Field User
Officer Operations, AI Alerts Monitoring, Plate Dossier & HITL Actions

Dedicated tactical API suite for patrol officers, duty officers, and field operators centered around ai_alerts. Enables non-admin officers to monitor live vehicle alerts, stream camera frames, acknowledge threats, record field actions, and perform real-time hotlist lookups.

📊 Dashboard & Metrics
GET /api/officer/dashboard
Daily alert counts, open vs acknowledged, hotlist hits, vehicle status.
👤 My Activity Only (Edge Cockpit)
GET /api/officer/my-activity
In-Vehicle Edge payload: Officer identity, assigned vehicle, 4 RTSP cameras, live GPS telemetry, duty stats & personal alerts.
🌐 City Fleet Grid Activity
GET /api/officer/fleet-activity
Situational awareness: Status & GPS for all 6 patrol vans, active cameras & citywide alert metrics.
🚨 Scoped Alerts Feed
GET /api/officer/alerts?scope=my|all
Filter by scope (my unit vs all fleet), status, vehicle, plate, type. Lightweight payload.
⚡ Live Stream Polling
GET /api/officer/alerts/live?scope=my|all&since_id=X
Fast terminal polling with hotlist siren audio triggers.
🖼️ Direct Binary Image Stream
GET /api/officer/alerts/:id/image
Streams JPEG/PNG directly for <img src="..."> tags.
✋ Acknowledge Alert
PUT /api/officer/alerts/:id/acknowledge
Mark status='A' (In Pursuit / En Route), record badge.
✅ Resolve & Close Alert
PUT /api/officer/alerts/:id/resolve
Mark status='C' with action_taken and resolution notes.
🔍 Plate Hotlist & Sightings Lookup
GET /api/officer/lookup/plate/:plate
Instant stolen check + all past GPS sightings across patrol cars.
🚔 Assigned Patrol Van & Cameras
GET /api/officer/my-vehicle
Vehicle model, registration, speed, 4 RTSP cameras, alerts.
SAMPLE OFFICER RESOLUTION PAYLOAD (PUT /api/officer/alerts/:id/resolve) 
{
  "action_taken": "INTERCEPTED",
  "comment": "Suspect vehicle pulled over at Navrangpura circle. Stolen vehicle recovered, FIR FIR 883/2024 verified.",
  "officer_name": "Inspector Rajesh Sharma (INSP-402)"
}

📡 Store-and-Forward Offline Queue Policy

1. When Online: Events push directly via HTTP POST with a 2000ms timeout.
2. When Offline: If 4G/5G disconnects or HTTP returns non-200, the payload is inserted into SQLite central_api_dispatch_queue.
3. Automatic Recovery: A background daemon retries pending events using exponential backoff (1s, 2s, 5s, 15s, 60s) once cellular connectivity resumes.
